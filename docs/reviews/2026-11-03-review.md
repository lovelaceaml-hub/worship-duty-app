# Review 2026-11-03: worship-duty-app

Whole-repository review, done in a cloud session on 2026-11-03 and
2026-11-04 with read-only Haiku helpers (client code, server code, docs and
history). Every finding below that is marked "verified" was checked against
the files; anything else says "unverified". No Firebase data, Sheet,
secrets, merges or deploys were touched.

## The short version

1. The repo is big because of old screenshots kept in git history, not
   because of the app. The app's files are 2.5 MB.
2. Two song collections (`songStats`, `setlists`) can be read and changed by
   anyone on the internet, because the Signal song ingest on the Mac writes
   them without signing in. Moving that ingest to the cloud fixes both the
   security gap and the Mac dependency.
3. The live app loads Firebase's browser library version 10.12.2, two major
   versions old. Worth a planned upgrade, not a quick bump.
4. The Cloud Functions packages had 16 known security advisories (1
   critical). The safe fixes are applied on this branch; 10 moderate ones
   remain that need a major `firebase-admin` upgrade.
5. PR #47 (calendar speed-up) was merged on 2026-10-23 but never released.

## 6. Why the repo is 56 MB and how to shrink it

Verified on the cloud copy: the app's files are 2.5 MB; git history is
about 45 MB, and 42.5 MB of that is 280 screenshot PNGs that used to live in
`docs/runs/` (added 2026-09-19, removed from the files on 2026-09-30). They
are gone from the current files but every clone still downloads them.
Installed packages (`node_modules`, about 270 MB when installed) are
not in git and not counted.

Options, safest first:

1. **Do nothing to GitHub; slim the Mac copy.** Delete the Mac folder and,
   if a local copy is still needed, clone again without old file contents:
   `git clone --filter=blob:none https://github.com/lovelaceaml-hub/worship-duty-app.git`
   (a few MB). Or work only in cloud sessions.
2. **Rewrite history to drop `docs/runs/`** with `git filter-repo`. Shrinks
   GitHub's copy to a few MB, but rewrites every commit on `main`, needs a
   force push, and breaks open PRs and other clones. Needs Anthony's
   approval; not recommended unless size causes a real problem.

## 7. What belongs in the cloud, not on the Mac

- **The Signal song ingest.** It is the one part of this app that only runs
  on the Mac, and it is why two collections are open to the internet.
  Moving it to a scheduled Cloud Function or GitHub Action (with its own
  service account) removes both problems.
- **Releases.** Already possible from GitHub (README "From GitHub"); the Mac
  `scripts/release.mjs` path can stay as a fallback only.
- **Tests that need Java (rules emulator).** Already run in GitHub CI; no
  need to install Java 21 on the Mac.
- **This repo's working copy.** Cloud sessions clone it fresh, so the Mac
  copy and its `node_modules` can go (option 1 above).
