## Suggestions, most valuable first

As written on 2026-11-10. What became of each on 2026-11-11 is in
[HANDOFF.md](../HANDOFF.md), "Released 2026-11-11": 1, 4 to 8 and 10 to 14
are live; 2, 3 and 9 were not done; 15 is live for the server libraries and
the Sheet tab, waiting for the browser SDK, and not done for the file splits.

1. **A changed PIN does not sign out other devices.** `functions/member-auth.js`
   `changeMemberPin` saves the new PIN but, unlike a reset, does not end the
   member's other sessions. Someone already signed in as that member stays
   signed in. Checked. Fix: end other sessions on a PIN change too.
2. **The shared starting PIN.** Ordinary members are never made to choose
   their own PIN, so anyone who knows the starting PIN and a member's name can
   sign in as them, then change their PIN. Already noted on 2026-11-03.
   Fix: every account chooses a PIN at first sign-in.
3. **The site passcode can be worked out.** `app/settings.sitePinHash` is
   readable without signing in and is a plain hash of 4 digits, so it can be
   reversed in seconds. Reported by the helper, rule lines read, not tested
   live. Fix: check the passcode on the server.
4. **`songStats` and `setlists` are open to the internet** (from 2026-11-03,
   still true: `firestore.rules:357`, `:361`). Fix: move the Signal song
   ingest to the cloud with its own sign-in, then close the two rules.
5. **Lost "New duty" alerts after a partly failed Sheet import.**
   `functions/sheet-io.js`: when any write in an import fails, no alerts are
   sent, and the next import no longer sees the writes that did succeed as
   new. Reported by the helper, not reproduced.
6. **A bad Sheet publish could blank many duties.** The published-link import
   treats a blank cell as "clear this duty"; the Entry-tab import does not.
   Live uses the Entry tabs, so this matters only if Write changes to the
   Sheet is turned off. Fix: refuse an import that would clear more than a
   few duties.
7. **Two people saving leaders at the same time** can lose one change
   (`functions/accounts.js`, read then write without a transaction). Rare.
8. **Anyone can lock a member out** for 15 minutes by entering five wrong
   PINs for their name, again and again. Fix: limit tries per device or
   address as well as per name.
9. **Song lists are listened to twice** (`app/sync.js` and
   `app/presider/data.js`), so every song edit is read twice. Small cost.
10. **Requests reload twice at each sign-in** (`watchRequests` runs twice).
    Harmless, a brief flicker at most.
11. **Song list save fallback** (`app/presider/data.js:94`): any failed update
    rewrites the whole list from the device's copy, which could undo a change
    made elsewhere moments before. Fix: only when the list does not exist yet.
12. **The maintenance screen** shows upcoming duty holders from the copy saved
    on the device before the site passcode is asked. Decide whether it should.
13. **Administrator override compares names exactly**; ordinary assigning
    accepts an older spelling. A member with an old spelling gets
    "name does not match" on an override.
14. **Leaders of more than 10 departments** would silently see requests for
    only the first 10. There are fewer than 10 departments today.
15. Still open from 2026-11-03: Firebase browser SDK 10.12.2 to 12, the
    `firebase-admin` 14 and `firebase-functions` 7 upgrades, splitting
    `permissions.js`, `functions/department-handlers.js`,
    `app/services/departments.js` and `app/lib/fill.js`, and the new-year
    Sheet tab made in two calls.

Looked at and correct as it is: keeping a member on a flagged duty marks
them available for that service in all their departments (README, "Change
requests and flagged duties"); the helper reported it as a bug.

Unused server code the helper found (not removed, server files):
`applyCorrection` in `functions/song-history.js`, `dutyCategory` in
`functions/sheet-lib.js`, `isValidPin` in `functions/member-auth.js`.
