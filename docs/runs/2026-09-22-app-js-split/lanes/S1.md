## Review

Fresh, same-session Sonnet 5 subagent, read-only, one round. It re-ran the verification suite independently (not trusting this record), independently re-extracted the roster from `DEPARTMENTS_SEED` plus `NAME_UNIFY_MAP` (45 to 47 names/aliases) and grepped the whole baseline directory itself, and spot-checked 20 manifest assignments against the plan's line-range table.

Verdict: FINDINGS, one blocking, two non-blocking.

**Blocking, fixed.** `tests/department-runtime-contract.test.mjs`'s "assignment callables are the only normal and override write boundary" test found the end of `assignDepartmentDutyForService`'s body with `app.indexOf('function seedState(', assignmentStart)`, unguarded by an `assert.ok` (unlike its sibling boundary two lines above). That relies on `seedState` following `assignDepartmentDutyForService` in text order, true only by coincidence in the untouched `app.js`. The manifest's `moduleOrder` places `core/state.js` (holds `seedState`) before `core/departments.js` (holds `assignDepartmentDutyForService`), so once Section 3 creates both files, `seedState` moves ahead in the concatenation and the `indexOf` call returns `-1`; `app.slice(assignmentStart, -1)` then silently returns an over-wide slice instead of failing, defeating the test's scoping without anyone noticing. Fixed by changing the end marker to `'function unassignDepartmentDutyForService('`, the next declaration in the *same* module (verified all of the test's target assertions still sit before that marker in the untouched tree), and adding the missing `assert.ok(assignmentStart >= 0 && assignmentEnd > assignmentStart, ...)` guard so any future ordering surprise fails loud instead of silently widening. Re-verified: `node --test tests/*.test.mjs` still 114 passed, 1 skipped, 0 failed.

**Non-blocking, fixed.** The four source-text test files concatenated modules with `.join('')`; a module file missing its trailing newline could let two files' content merge across a `\n`-anchored boundary search. Changed to `.join('\n')` in all four files. Re-verified: full test suite and `node tests/ui-qa.mjs` (against a local static server) both still green.

**Non-blocking, not fixed (noted, dormant today).** The column-zero declaration regex in `scripts/check-app-split.mjs` could in principle false-positive on `function `/`export ` text sitting inside a multi-line template literal or comment at column 0. The reviewer confirmed `app.js` has no multi-line template literals today (its 10 backticks are all single-tick markdown references inside comments) and future sections are pure code motion, so this risk stays dormant; left as-is rather than adding untested defensive complexity to a checker whose whole purpose is catching exactly this class of drift.

No other findings. Everything else (privacy grep, `design-gallery/test.mjs`'s minimal diff, manifest spot-checks, dash scan, `app.js` byte-identity) independently confirmed clean.

**Self-caught after the review, before committing the fixes above.** Staging the review fixes showed `tests/fixtures/app-js-split/load-effects.json` as modified even though nothing should have touched it: `design-gallery/parity.mjs --compare` was unconditionally re-running `captureLoadEffects` and overwriting that committed fixture on every call, and `timersScheduled` is not perfectly deterministic run to run, so every verification pass left the working tree dirty. Fixed: `recordAll()` now takes a `captureLoad` flag, and only `--record` sets it; `--compare` reads the fixture but never rewrites it.
