**The central problem this section had to solve**: `render` and other
appearance-dispatch functions were already known (from Section 3) to be
monkey-patched by `design-gallery/host-bridge.js`, spliced as literal text
right before `app.js`'s closing `init();` call. The real patched set, after
two review rounds corrected two rounds of over-attribution (see Review
below), is exactly **`host-bridge.js`'s own 11**: `render`, `renderSchedule`,
`renderMy`, `renderManage`, `renderManageServices`, `renderManagePlanning`,
`renderManageRequests`, `renderManagePeople`, `renderFeatures`,
`renderManageData`, `renderSiteLock`. `renderUnlock`, `renderCreatePin`,
`renderServiceCard` and `songCtx` each have a same-named reassignment
somewhere in `design-gallery/build.mjs`'s raw source inputs, but none of
those four ever actually reach `app.js`'s own scope once `build.mjs`'s own
transforms run (see Review for the exact mechanism each time); they are
ordinary imports, no shadow, no setter, no rename.

Fixed by generalizing the private-local-plus-setter pattern Section 3 used
for `render`/`renderBanners`/`pulse`: `app.js` keeps its own mutable `let`
for each of the 11, seeded from the real import before any gallery code
runs, so the monkey-patch lands on `app.js`'s own local instead of a
read-only ES import binding. Every other module that needs the live,
possibly-patched version receives it through a setter called from `init()`,
after the injected gallery code has already run. Two of the 11
(`renderSiteLock`, `renderManageServices`/`renderManagePlanning`/
`renderManageRequests`/`renderFeatures`/`renderManageData`, six names, two
collision sites) are both owned by and internally dispatched-to from within
their own module (`views/shell.js`'s `render()`, `views/manage.js`'s
`renderManage()`), so the real implementation keeps its name and the
internal call site is renamed to an `active`-prefixed local instead (seven
allowlist entries: one for `renderSiteLock`'s call, six for `renderManage`'s
dispatch since `renderManageServices` is called from two branches).
`renderManagePeople` is reassigned but never called by name anywhere in the
app (confirmed by grep against the frozen baseline), so it needs only the
`app.js`-local shadow, no rename, no setter.

Fixed a real checker gap: `buildCurrentDeclarationIndex` treated every
`app.js`-local declaration as automatically eligible to be a baseline name's
"current home" regardless of export status, which collided with the new
`app.js`-local shadow `let`s. Fixed by excluding an `app.js` `let` whose name
the manifest assigns to a different, already-existing module. All 11
existing checker behavior tests still pass unmodified.
